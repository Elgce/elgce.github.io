你忘记的名字是 Muon，但不是全局替换

GR00T 当前的 Muon + Auxiliary Adam 方案

截至 2026-08-30 的本地 GR00T 工作树，通用 training config 默认仍为 adamw_torch_fused 且 use_muon=False；若实验显式开启 Muon，hidden matrix parameters 走 Muon，其余参数走带 decoupled decay 的 auxiliary Adam update。

直接回答

最近加入/部分训练脚本切到的是 Muon。准确说法不是“GR00T 从 AdamW 全面换成 Muon”，而是“可选的 MuonWithAuxAdam 混合 optimizer；默认路径仍是 fused AdamW”。

1. 当前代码证据

本地路径读到的逻辑
groot/core/training/configs/training/training_config.pyuse_muon: bool = False；optim = "adamw_torch_fused"；muon_lr = 0.005
groot/core/training/experiment/trainer.pyuse_muon 为 false 走父类 optimizer；为 true 调 create_optimizer_muon()
groot/core/utils/muon.pyMuonWithAuxAdam 与 single-device batched variant；两组都独立做 decoupled decay
多个 groot/vla/omni/scripts/train/*.sh已显式传 --training.use_muon，说明部分 recipe 正在使用

本地历史还包含 [muon] Add torch.optim.Muon backend、Add Muon Optimizer, Configs for XDOF 等提交，所以“最近换成什么”的记忆点确实是 Muon。

2. Parameter routing

if p.ndim >= 2 and "embed" not in name and "lm_head" not in name:
    hidden matrix → Muon
else:
    embedding / head / bias / norm / scalar → auxiliary Adam

each side is split again into:
    decay group       weight_decay = configured value
    no-decay group    weight_decay = 0

因此一个 optimizer object 管多类 param groups，但 step rule 不同。选择主要依赖 tensor rank 与 name；加入新 module/改命名时必须重新 audit routing。

3. Muon 组的更新

hidden matrix 维护 momentum buffer，调用 muon_update 做 Newton–Schulz orthogonalization，然后：

W ← (1−lr_muon·wd)W − lr_muon·orthogonalized_momentum

Muon 有独立 muon_lr，不能用 AdamW 的 learning_rate 直接解释。实现支持 distributed 版本，也有 single_batched 把相同 shape matrices batch 化减少 overhead。

4. Auxiliary 组的更新

embedding/head/1D 等参数维护 exp_avg、exp_avg_sq 与 step，做 bias-corrected Adam update；随后显式 p.mul_(1−lr·weight_decay) 再加 update。因此虽然类名叫 AuxAdam，weight decay placement 是 AdamW-style decoupled decay。

5. 为什么这样混合合理

  • Transformer/DiT hidden linear matrices 正是 Muon 的 2D geometry 对象；
  • bias/norm 没有 matrix polar factor；
  • embedding 与 LM head 的形状、语义和 update scale 特殊；
  • auxiliary Adam 保留成熟的 per-coordinate adaptive scale；
  • 一个 wrapper 统一 step/checkpoint，避免两个 optimizer 的 scheduler 与同步逻辑分裂。

6. “默认仍是 AdamW”与“最近用了 Muon”不矛盾

配置默认回答“未指定实验参数时走什么”；训练脚本回答“某个 recipe 实际开启什么”。当前多份 PupGo、N1.6/N1.7、Agibot scripts 显式开启 Muon，但全局 default 为 false。判断某个 run 必须看最终 resolved config/launch command，不能只看 dataclass default 或 commit 标题。

7. 切换时不能直接复用什么

  • LR：Muon 与 auxiliary Adam 各有 LR，数值尺度不同；
  • optimizer state：Adam m/v 不能直接变成 Muon momentum；weights-only resume 会有 transient；
  • scheduler：代码需确认是否同时缩放各 param groups；
  • weight decay：各组 decay/no-decay routing 要一致；
  • checkpoint：从非 Muon optimizer 恢复必须明确定义 state mismatch 行为。

8. 最值得加的 assertions/logging

  1. 打印每组 parameter names、tensor count、numel、LR、decay；
  2. assert 每个 trainable parameter 恰好出现一次；
  3. 记录 Muon 与 Adam 组的 grad/update/weight norms；
  4. 监控 Newton–Schulz nonfinite、optimizer step time 与 distributed imbalance；
  5. 在 checkpoint resume 后对比第一步 LR/state/parameter delta；
  6. 对相同 tokens 比 validation loss，再比较 wall-clock。

9. 一句话决策

目标建议起点
最稳、复现旧 recipe保持默认 fused AdamW
hidden-matrix training 加速实验显式开启 Muon，保留 auxiliary Adam，并独立 sweep
只做 LoRA/小 head finetune先检查 trainable params 是否根本会命中 Muon；很可能主要仍是 Adam
要宣称“更快”同时给 loss/token、loss/wall-clock、peak memory 与 end eval
最容易踩的坑：

看到 optimizer object 名字是 MuonWithAuxAdam，不能假设全部参数都走 Muon；看到默认 use_muon=False，也不能假设某个 launch script 没开启。最终 resolved parameter routing 才是事实。

自测

1. 当前 GR00T 默认 optimizer 是什么？

通用 training config 默认 adamw_torch_fused，且 use_muon=False。

2. 开 Muon 后 embedding/head 怎么更新？

它们不走 Muon，而走 auxiliary bias-corrected Adam update，并独立做 decoupled weight decay。

3. 为什么某个 run 不能只看默认 config？

launch script/experiment YAML 可显式传 --training.use_muon 覆盖 default。
