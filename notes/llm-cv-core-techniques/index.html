先建立一张不会过期的地图

过去十年出现过成千上万个模型名，但真正沉淀下来的主线很少。我目前把它们压缩成四句话：

  1. 模型骨架逐渐统一到 Transformer。
  2. 训练方式逐渐统一到大规模自监督预训练。
  3. 文字、图像、视频和动作逐渐被表示成可共同处理的 token。
  4. 能力越来越依赖后训练、推理时计算和部署系统，而不只是预训练参数量。

它们现在只是地图，不是结论。后面的每一章都要用公式、最小例子、反例和 GR00T 中的真实代码把它们重新推导出来。

Chapter 01

Token、Embedding 与自回归训练

大模型面对的第一个问题不是“如何推理”，而是：怎样把原始信息变成神经网络能计算的东西，以及怎样从没有人工任务标签的数据中获得训练信号？

1. Token：模型真正读到的单位

神经网络不能直接接收“robotics”这个字符串，它只能处理数字。Tokenizer 先把输入切成一串有限词表中的单元，再把每个单元映射为整数 ID。下面只是示意，不同 tokenizer 的切法会不同：

"I love robotics"
        ↓ tokenizer
["I", " love", " robot", "ics"]
        ↓ vocabulary lookup
[40, 1842, 9201, 1127]

token 不等于单词。它可能是一个字、子词、标点、图像 patch、离散动作，甚至由模型学习出的 latent code。选择怎样 tokenization，本质上是在决定：模型用什么“积木”表示世界，以及一段信息需要多少步才能处理完。

关键区分：

token 是离散符号；token ID 只是它在词表中的编号。ID 之间没有数值距离意义——编号 100 并不比编号 10“大十倍”。

2. Embedding：把编号变成可学习的坐标

整数 ID 不能直接表达相似性，所以模型维护一个可训练矩阵 $E \in \mathbb{R}^{V \times d}$。词表大小是 $V$，每个 token 用 $d$ 维向量表示。查第 $i$ 行便得到 token $i$ 的 embedding：

$$\mathbf{e}_i = E[i]$$

训练开始时这些坐标通常接近随机；为了降低预测误差，它们与网络其他参数一起被梯度更新。经常出现在相似上下文中的 token，最终可能形成相近或结构相关的表示。

但这里还有一个容易混淆的地方：输入 embedding 是 token 刚进入模型时的向量；经过多层 Transformer 后得到的是带上下文的 hidden state。同一个 token 在不同句子中的输入 embedding 相同，但最终 hidden state 可以完全不同。

3. 自回归训练：把一条序列变成许多监督题

“自回归”（autoregressive）的意思是：把一个序列的联合概率，拆成每一步在过去条件下的概率。

$$p(x_1, x_2, \ldots, x_T)=\prod_{t=1}^{T}p(x_t\mid x_1,\ldots,x_{t-1})$$

这不是神经网络特有的技巧，而是概率的链式法则。模型真正学习的是每一个条件分布 $p(x_t\mid x_{<t})$。

例如一条序列 I love robotics <EOS>，一次训练就能产生多道题：

看到：<BOS>                 → 预测：I
看到：<BOS> I               → 预测：love
看到：<BOS> I love          → 预测：robotics
看到：<BOS> I love robotics → 预测：<EOS>

训练时不必真的循环四次。通过 causal mask，Transformer 可以并行计算所有位置，但每个位置只能看见自己左边的正确 token。这种把真实历史提供给模型的方式叫 teacher forcing。

4. Loss：模型怎样知道自己错了

在每个位置，模型输出整个词表上的 logits，经 softmax 变成概率。若正确 token 是 $x_t$，该位置的交叉熵就是：

$$\mathcal{L}_t=-\log p_\theta(x_t\mid x_{<t})$$

整条序列通常取所有有效位置的平均。最小化这个 loss，等价于最大化训练数据在模型下的 likelihood。因此可以把 next-token prediction 理解成：不断提高真实后续在模型分布中的概率。

训练时

每个位置看到真实历史；所有位置并行算 loss。速度快，而且早期预测错误不会污染本次样本后面的输入。

生成时

真实的下一个 token 不存在，只能把模型刚生成的 token 接回输入。前面的错误可能改变后续分布。

这就是常说的 train–inference mismatch 或 exposure bias。它不是说 teacher forcing “错了”，而是说明训练条件和自由生成条件并不完全一致。

5. 放到机器人动作模型里

文本自回归预测下一个语言 token；机器人模型可以预测下一个动作 token、动作维度，或者一小段 action chunk。抽象形式相同：

$$p(a_{1:T}\mid o)=\prod_{t=1}^{T}p(a_t\mid o,a_{<t})$$

其中 $o$ 可以包含图像、语言指令和机器人状态。差别在于动作常常是连续值，而且控制要求低延迟、平滑和闭环纠错。因此机器人系统不一定逐个离散 token 生成；它也可能用 diffusion、flow matching 或并行 action chunk。

到这里应该形成的直觉：

“自回归”描述的是概率分解和生成顺序，不等于“语言模型”，也不等于“必须使用 Transformer”。RNN、Transformer，甚至其他网络都能参数化这个条件分布。

本章自测

先用自己的话回答，再展开参考答案。

1. 为什么 token ID 不能直接作为一个连续数值喂给模型？

因为 ID 只是类别编号，数值大小和距离没有语义。Embedding lookup 把每个类别映射到独立、可学习的向量坐标。

2. 自回归训练为什么可以并行，而推理通常不可以？

训练时整条正确序列已知，causal mask 能让所有位置同时预测各自的下一个 token；推理时第 $t+1$ 步的输入依赖第 $t$ 步刚生成的结果。

3. Next-token prediction 和 maximum likelihood 是什么关系？

链式法则把序列 likelihood 分解成逐 token 条件概率的乘积；逐位置最小化负对数概率，就是最小化负 log-likelihood。

我的当前复述

一条原始序列先被 tokenizer 变成离散 token，再由 embedding 变成可学习向量。自回归模型用过去预测下一步；训练通过 causal mask 同时制造很多 next-token 题，并用交叉熵提高真实后续的概率。生成时没有老师给正确历史，所以模型必须消费自己的输出，错误也可能向后累积。
